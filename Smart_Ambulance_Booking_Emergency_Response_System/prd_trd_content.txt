 Task 1: Product Requirements Document (PRD)
1. What is a PRD?
A Product Requirements Document (PRD) describes what a product should do, who it is for, and what features it should
provide. It helps the development team understand the project's goals, user requirements, and expected functionality
before development begins.
2. Project Goals and Objectives
The main goal of the Smart Ambulance Booking and Emergency Response System is to provide a fast, reliable, and
organized platform for requesting ambulances and coordinating emergency response.
Objectives:
  Allow users to book an ambulance quickly.
  Show available ambulances based on location and status.
  Share the patient's pickup location.
  Provide live ambulance tracking and estimated arrival time.
  Connect patients with ambulance drivers and emergency services.
  Reduce delays in emergency response.
  Provide an organized booking and emergency history.
  Improve communication during emergencies.
 3. Features and Requirements
User Features:
  User registration and login.
  Search and request available ambulances.
  Select ambulance type.
  Enter pickup and destination details.
  Share live location.
  Track ambulance in real time.
  Receive booking and arrival notifications.
  View booking and emergency history.

 Task 3: Abstract
Project Title
“Smart Ambulance Booking and Emergency Response System”
Abstract
The Smart Ambulance Booking and Emergency Response System is a full-stack web application designed to make
ambulance booking and emergency coordination faster, easier, and more reliable. In emergency situations, delays in
finding an available ambulance, sharing the correct location, and communicating with drivers can increase response time.
The proposed system provides a centralized platform where users can register, request nearby ambulances, enter pickup
and destination details, share their live location, and track the assigned ambulance. Ambulance drivers and administrators
can manage requests, update availability, and coordinate emergency trips.
The system integrates web technologies, backend APIs, databases, maps and location services, real-time communication,
and notification services. It maintains booking and emergency records so that users and administrators can review
previous requests.
The expected outcomes are faster ambulance discovery, reduced response and communication delays, improved location
accuracy, better ambulance utilization, and a more organized emergency response process.
Overall, the project solves the limitations of manual ambulance searching and communication by providing a centralized,
real-time, user-friendly digital platform for ambulance booking, tracking, and emergency coordination.
